# 用户态内存管理

物理页分配取得一个 4096 字节资源；块分配把这个页切成应用所需的较小空间。
`ael_alloc(96)` 通常不调用内核，只更新用户态空闲块记录。
每次最多 4096 字节，不拼接多页大对象；这是本阶段的明确 API 限制。

## 页面生命周期

```text
空记录 -> claim(index,generation) -> 选择窗口 VA -> map
              |                         |
              | map 失败 -> release 回滚 |
              +-------------------------+
               应用 load/store / 块管理
                     -> unmap（可重新 map）
                     -> release（撤销全部别名并归还）-> 空记录
```

page pool 保存完整句柄、owned/mapped 和 VA，不把 PFN 当权限。
选择 `[0x09000000,0x09010000)` 中最早可用页，EBUSY 时尝试下一页；其他错误立即返回。
未映射的 claimed 页也占额度。acquire 的 map 失败会 release；若 release 自身失败，记录保持可重试，
不会在用户元数据中伪装成已归还。内核在域退出或故障时仍负责最终清理。

额度来自只读查询。当前内核每域四页、全局十六资源槽；本库元数据最多支持窗口十六页，
绝不因用户策略切换扩大配额。外部映像/BSS/栈和内核页表不在这些可释放的资源中。

## 块表与策略

每个 arena 对应一页，记录按地址排序的 offset/size/used；元数据位于本 LibOS 的 BSS，
不嵌入应用 payload。16 字节对齐，因此一页最多 256 个最小块；表容量足以覆盖最坏划分。
当前为十六个可能 arena 预留表（约 32 KiB BSS），换取容易审查的有界算法，尚未优化元数据占用。

1. 对申请长度先检查 1..4096，再向上取整，避免 size_t 溢出。
2. first-fit 选择按 arena/地址顺序第一个足够大的空闲块；best-fit 扫描全部已有空闲块，取最小合适块。
3. 块过大则分裂成已用块和剩余空闲块；没有合适空间才取得并映射新页。
4. free 只接受精确活跃块起点，将它标为空闲并合并相邻空块。
5. 空页默认保留用于复用；trim 才归还全空页。destroy 在仍有活跃块时返回 EBUSY。

策略实验使用完全相同的内核：申请 `64,256,64,128,64`，释放中间的 256/128 字节块，再申请 96。
first-fit 复用 256 的起点，best-fit 复用 128 的起点；两种行为都在宿主与真实 CPL3 中断言。
两种构建只改变用户态 policy，内核无需改代码、更换映像或增加分配器。

## 错误与安全边界

free(NULL) 成功；未知地址、页内非块起点、当前已空闲块均 EINVAL，不读取该指针内容。
若原始指针已经被释放且地址后来复用，指针本身无法区分旧/新对象；不能声称可检测全部悬垂指针。
用户越界、修改元数据、或绕过包装直接调用 ABI 会使本域库状态无效，属于同域不可信代码问题；
内核继续独立验证所有权和权限，不信任本库的表。

ENOMEM 代表物理资源/页表不足；ENOSPC 代表额度、资源槽或窗口耗尽；失败不增加访问权限。
release 失败保留对应记录，trim 允许已完成的部分进度并可重试。只有新建 pool/heap 才能调用 init，
不能重新初始化一个持有资源或活跃分配的对象。本 API 非线程安全。
